## What the stack actually is

The brief describes a Lovable React/TypeScript app on Vercel. The code shows two front ends in one repo, and that shapes every finding below:

- **The marketing site is Astro 4**, pre-rendered to static HTML (`web/`, `astro.config.mjs`, `output: "static"`). Every marketing page, including the homepage, is `web/pages/*.astro`.
- **The app is a Vite + React 18 SPA** (`src/`), built a second time into `dist/_spa` with base `/_spa/`. `vercel.json` rewrites every non-static path to it. It serves `/assessment`, `/guide/*`, `/founder`, `/practitioner`, `/apothecary/*` and the legal pages.
- **The backend is Supabase:** Postgres with RLS, 39 Deno edge functions, 151 migrations on `main`. Eleven Vercel cron schedules, served by ten handlers in `api/cron/`, forward to edge functions with the service-role key.
- **Environment prefixes are `VITE_` and `PUBLIC_`, not `NEXT_PUBLIC_`.** This is not Next.js. Anything with those prefixes is compiled into public JavaScript. Server secrets live in Supabase function secrets and Vercel project env vars, read only by `api/` and edge functions.

## 2. Security audit

### Credentials and configuration

| Check | Result |
|---|---|
| Service-role key in browser code | None. `src/` and `web/` contain no `service_role` reference. The client uses only `VITE_SUPABASE_URL` and the `sb_publishable_` key. |
| Secrets committed to git | None found. The only key-shaped strings are `sk_live_...` placeholders in two script comments. `.env` is gitignored, and `.env.example` holds names only. |
| Public env prefix | `VITE_`/`PUBLIC_` values are public by design. The two unused ones were removed from `.env.example`, and the server-side variable names are documented. |
| Security headers | There were none. #505 adds `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: SAMEORIGIN` and `Permissions-Policy`. A CSP was left out because it needs an analytics allowlist. |
| Leaked-password protection | Off. It needs the Supabase Pro plan, so it is a founder decision. |

### Row Level Security and grants (live database)

Every public table has RLS enabled, and 49 internal tables are deny-all, reachable only by the service role. Reference tables are public-read; herb junctions are Seed-tier gated; person profiles, favorites and diagnostic data are owner-scoped. The tier paywall runs through owner-privileged views with `CASE` masking on `current_user_at_least()`, and that is intentional.

The gaps were in grants, not policies:

| Gap (verified live) | Severity | Resolution |
|---|---|---|
| `profiles_self_update` let a user write their own `stripe_subscription_id`, `is_founding_member` and billing period columns. With a fake subscription id, `stripe-webhook` ignored the cancellation and the paid tier stayed. | high | #503 narrows client UPDATE to `display_name`, since no client code writes profiles. #504 makes the webhook check with Stripe that the other subscription is real, live and the same customer's. |
| `waitlist_apply_resend_event` EXECUTE granted to `anon`. With the public key, anyone could unsubscribe any list address or overwrite its metadata. | high | #503, service role only. |
| `weekly_trends_snapshot` (lead and traffic totals) EXECUTE granted to `anon` | medium | #503, service role only |
| `is_internal_tester`, an oracle over a personal-email list, EXECUTE granted to `anon` | low | #503, service role only |
| `founder_course_funnel` anon EXECUTE, and no `pg_temp` in search_path. Guarded by `is_founder()`. | low | #503; also a sweep so no `founder_*` RPC is anon-callable |
| `clinical.*` tables had no RLS, only revoked grants | low | #503 enables RLS with no policies. Definer RPCs keep working. |
| Unused anon-readable views and legacy tier helpers | low | #503 revokes them and keeps them for the service role |
| Six functions with a mutable search_path; SECURITY DEFINER functions without `pg_temp` | low | #503 pins them |

**Root cause, recorded in the migration header:** `REVOKE ALL ... FROM PUBLIC` does not remove the explicit `anon` and `authenticated` grants Supabase adds to every new function and view. Several migrations believed an object was service-role only when it was not. Revoke from `public, anon, authenticated` by name.

The migration ends with assertions that roll back the whole transaction if any of these grants survive.

### Injection and client-side vectors

- `dangerouslySetInnerHTML` appears only in the unused shadcn `chart.tsx`, with developer-controlled config. Astro `set:html` is used only for `JSON.stringify` JSON-LD and a constant inline script.
- Links built from database JSON or `localStorage` now render only for http(s) URLs or known Pattern slugs (#505).
- Customer-facing forms never show raw Postgres text (#505).
- Real subscriber email addresses in test fixtures, and a real customer's name in an audit script, were replaced with synthetic values (#505, this PR). **They remain in git history.** Rewriting history on protected `main` is a founder decision.

## 4. Architectural concerns that need a decision

These are flagged, not implemented. Each is in Appendix B with its question.

1. **The migration history cannot rebuild the database.**
   - One migration is truncated mid-statement.
   - Several tables and RPCs exist only in production: `crm_people`, `founder_crm_*`, `feedback_submissions`, `nurture_email_queue`, `founders_interest`.
   - Two migrations insert their own history rows.

   Until a dump-based baseline exists, `db reset`, branches and grant tests cannot work.
2. **Two front ends duplicate the marketing surface.** React copies of the homepage and results page still render on client-side navigation, and the navbar and footer are maintained twice by hand. Decide whether to retire the React copies and keep the SPA to the app routes.
3. **Global mobile CSS changes the look site-wide.** Every `section button` is forced to full width, and headings and paragraphs are hyphenated site-wide. Removing the rules is a visual change that needs a before-and-after pass.
4. **Brand fonts never apply.** `font-body`, `font-accent` and `font-display` utilities do not exist in the Tailwind config, so about 1,300 elements fall back to the default serif. Registering them is a redesign-scale visual change.
5. **Founder identity is a hard-coded email string** in `is_founder()` and five client files, and the JWT email claim is the only factor. A role table or a claim set by the service role would be sturdier.
6. **Prices and product facts are hand-duplicated** across pages, emails, JSON-LD and three constants modules: herb count, trim size, K-12 claims, the Arizona ESA fee rate. #505 consolidates the Apothecary prices; the rest touch copy.
7. **List campaigns are code edits.** Each `list-announce` campaign means editing and redeploying a service-role function.
8. **Broadcast resume.** An interrupted cohort send cannot be resumed without re-mailing everyone. For legally required delay notices this needs a per-recipient send log. Idempotency keys (#504) are the first half.
9. **Crons that can outlive their platform limit.** Edge-runtime crons wait on functions that can take about 70 seconds. The weekly digest and evening recap have no run-claim or retry.
10. **ESA automation hardening.** Invoice numbers are used before their rows exist, the confirm token is consumed before payment applies, and fulfilment cannot resume a partial failure. These were held back because the system shipped on 2026-09-14 and is still changing.
11. **Repository weight.** 115 MB of tracked binaries, about 66 MB of them unreferenced, with no Git LFS. Seven Python scripts that production depends on live outside this repo.
12. **`/homeschool/welcome` and `/guide/success`** may be live Stripe success URLs or dead. The Stripe dashboard settles it.

## 5. Committed fixes

Every change is listed in Appendix A with its location, what changed and its status. The highlights:

**Production was broken in two places**

- **The ESA daily cron fails on every invocation.** `api/cron/esa-daily.ts` declared no Edge runtime, so Vercel ran a Web Request handler on Node. A live request on 2026-09-14 returned `FUNCTION_INVOCATION_FAILED` before the secret was even checked, while its sibling crons returned 401. The 14-day family reminder and the founder's 30-day unpaid alert therefore cannot run. #505 fixes it through the shared cron handler, and they start running after merge.
- **The `/courses` tier grid was broken on desktop.** The Tier 1 textbook card took a column of its own and pushed Tier 3 to a second row. #505 fixes it; a headless browser comparison of `main` against the branch shows the grid going from four children to three.

**Correctness**

- FTC delay notices carried the quiz footer, because the replacement string never matched the rendered `&rsquo;`. Their subject could also contradict the per-order opt-in in the body, and a notice could send without its evidence row. All fixed in #504.
- Repeat signups re-armed a day-7 Starter offer that had already been sent. A gateway error on the quiz lookup re-sent quiz Email 1. Both fixed.
- A Starter delivery stuck in `in_progress` after an isolate died was never retried. It is now reclaimed after 15 minutes.
- A purchaser name outside the PDF font's character set (for example "Łukasz") threw inside the paid PDF stamp, so the buyer got no files. Fixed and tested with the real `pdf-lib`.
- Past-due subscribers saw "Free" with their past-due notice hidden. A failed profile read silently reset the active profile and badged herbs against the wrong person's Pattern. A double tap on a quiz answer could skip a question or submit the lead twice. All fixed in #505.

**Resilience and performance**

- An app-wide error boundary.
- Code splitting: the SPA entry chunk went from 1,150 KB to 777 KB.
- A one-time reload when a stale chunk 404s after a deploy.
- A time budget on the nurture drain.
- `waitUntil` for fulfilment kicks.
- Retries on gateway errors for repeat-safe calls.
- `deno check` now passes for all 39 functions; two failed on `main`.

**Accessibility and polish**

- 113 buttons nested inside links, which is invalid HTML with a double focus stop, became single styled links. Size and position were measured identical at 375 px and 1280 px on 14 pages.
- The profile delete dialog is now an accessible dialog, the mobile menu closes on Escape and returns focus, and the founder dashboard has a keyboard tablist and modal focus.
- The ESA invoice form has native validation and stable rows. The quiz has labelled inputs and announced progress.
- The feedback button no longer sits under the cookie banner on phones.
